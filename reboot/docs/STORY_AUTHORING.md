# Сценарні катсцени UA Force

Це основа для майбутнього сценарію, а не затверджений сюжет. Два короткі демонстраційні епізоди додані на початку «Тихого берега» й «Острова свободи». Вони показують патруль, рух камери, постановочну дію героя та повернення через прапор.

## Що можна описати без програмування

Для кожної сцени заповніть коротку картку:

- Назва та місце: операція, орієнтир і момент запуску.
- Мета сцени: що гравець має зрозуміти або відчути.
- Учасники: конкретні герої, вороги, інші персонажі.
- Кадри по порядку: куди дивиться камера; хто куди йде, стрибає, повертається, прицілюється або жестикулює; тривалість кожного кадру.
- Репліки українською та звукові акценти. Нову озвучку замовляємо окремо; написаний текст сам по собі не створює запису голосу.
- Вихід: де залишаються учасники, що починається після сцени, чи змінюється ціль.
- Альтернативи: що робити, якщо ворога вже знищили або гравці прийшли з іншого боку.

Приклад задуму: біля складу патрульний озирається на шум; камера переводиться на героїв; один рухається до входу, другий прикриває тил; коротка репліка; прохід синьо-жовтого прапора; керування повертається.

## Поточний формат реалізації

`src/game/story-scenes.ts` містить `STORY_SCENES`. Кожна сцена задає `id`, індекс операції `mission`, координату входу `triggerX`, основний пост `guardPost`, необов’язкові `extraGuards` та послідовність `beats`.

```ts
{
  id: 'warehouse-approach',
  mission: 0,
  triggerX: 120,
  guardPost: 118,
  extraGuards: [134],
  beats: [
    { seconds: 1.4, camera: 'guard', guard: { dx: 1, face: 1 } },
    { seconds: 1, camera: { x: 125, y: 5 },
      enemies: { 0: { face: -1, pose: 'aim' }, 1: { dx: -1 } },
      sound: 'enemySuspect' },
    { seconds: 1.5, camera: 'team',
      players: { 0: { dx: 1.5, jump: true }, 1: { pose: 'cast', face: -1 } },
      caption: 'Прикривай. Я зайду збоку.' }
  ]
}
```

Це приклад формату, не активна третя сцена. Пост — початкова `anchor`-координата наявного ворога; `enemies[0]` — основний, наступні індекси відповідають `extraGuards`. Відсутні додаткові учасники пропускаються; якщо основний уже загинув, сцена не блокує гру.

`dx` — зміщення від позиції учасника **на початку всієї сцени**, а не від попереднього кадру. `player` задає спільний рух героїв; `players[0/1]` перевизначає його окремо. `guard` — скорочення для основного ворога, `enemies` дозволяє різні дії кількох ворогів. Пози `idle`, `aim`, `cast` та біг/стрибок використовують наявні піксельні анімації; `cast` тут лише поза, не бойове застосування ульти. Камера має цілі `team`, `guard`, явну координату або `cameraOffsetX` біля основного ворога.

Рух використовує фізику та колізії: персонаж не проходить крізь ящик чи стіну, кадр закінчується за таймером навіть при перекритому шляху. Для нової сцени обов’язково перевірити маршрут. Нові унікальні спрайтові анімації, повноцінні діалоги з вибором і зміни сюжетних цілей потребують окремої реалізації.

## Керування й безпека

Під час сцени звичайні команди гравців не виконуються; бій, снаряди, таймер місії й фоновий AI заморожені. Рухаються лише призначені учасники. Пауза працює, пропуск доступний кнопкою або підтвердженням з клавіатури/геймпада. Автоматичний кінець і пропуск проходять через той самий прапор тривалістю 0.72 с, далі відновлюються звичайні керування та AI. Гравці отримують короткий захист після виходу, бойові заряди не витрачаються сценарними позами.

Тригери спрацьовують при перетині точки; якщо герой стрибає, запуск чекає приземлення в зоні наступних 8 одиниць. Поточні постановки розраховані на пішу команду: у танку запуск не примушує гравця вийти. Сцена програється один раз на поточну спробу операції, після повного перезапуску рівня доступна знову. Смерть основного учасника або пропущена зона не створює зависання.

Кооп: тільки host просуває сцену; beat, час, камера, учасники й переміщення передаються гостю. Пропуск гостем — запит host. Особистого таймера катсцени на гості немає.

## Спільний екран

Поле — 640×360, 16 пікселів на одиницю світу. CSS масштабує його як 16:9 з полями, тому широкий монітор не дає більшої дистанції. Максимальна відстань між двома гравцями — 30 по горизонталі, 12 по вертикалі. Камера спільна, не залежить від локального номера гравця. На межі зупиняється той, хто збільшує відрив; нерухомого друга не тягне за собою. Якщо обоє розбігаються, залишок місця ділиться порівну відповідно до руху. Танк обмежується разом із водієм. Далекий чекпоінт при смерті замінюється безпечною позицією біля живого друга.

Під час катсцени камера коопу також тримає обох героїв у видимому полі, вище нижньої смуги з реплікою. Це обмеження двох керованих гравців; призвані NPC продовжують користуватися власною логікою слідування.

## Перевірка

`tools/verify-story.html?silent=1`: обидві сцени, покадровий крок, пропуск, лідер біля межі й наздоганяння. У полігоні немає Sound або аудіовиходу. Автоматичні перевірки: `tests/story-screen.test.ts`.

Формат коопу оновлено до uaforce-coop-2: застарілий клієнт отримує прохання оновити обидві сторінки, щоб не показувати іншу камеру під час сцени.

Перевірено 2026-09-10: 299 автоматичних тестів пройдено; після оновлення версії протоколу додатково пройдено 14 тестів коопу й транспорту. Production build: 106 файлів, 70.96 MiB. Беззвучна браузерна перевірка обох сцен, спільного екрана та прапора — без помилок.

`tools/verify-story-online.html?silent=1` на дозволеному локальному порту 5178: два справжні WebRTC-клієнти, 193 отримані стани, збіг камери host/guest, блокування атак, пропуск від гостя, спільний прапор, відновлення гри й межа 30 одиниць — усі перевірки пройдено. Це перевірка двох клієнтів на одному комп’ютері; окрема мережа друга в цій сесії не тестувалася.
